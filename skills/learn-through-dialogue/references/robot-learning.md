# Robot Learning: A Tutorial — 問いの設計例

出典：[arXiv:2510.12403](https://arxiv.org/abs/2510.12403)。以下は原文の翻訳ではなく、教材につなぐための自作の問い。ページはこのリポジトリに保存した v1 PDF（76ページ）に対応する。

このリポジトリでは `materials/robot-learning-tutorial/README.md` を再開位置、`docs/environment.md` を環境情報の基準とする。学習済みの問いを機械的に最初から繰り返さない。別の場所で使う場合は利用者が指定した教材ノートを探し、進捗を推測しない。

## 導入の問い

一度に提示するのは一問。下記の補足は回答を受けてから、必要なものだけ使う。

| 問い | 回答から見る点 | 必要に応じた補足 |
| --- | --- | --- |
| コップの位置が変わるなら、つかむためにどんな情報が必要？ | 外部環境と自分の状態を考えられるか | 位置の座標系、関節角度、姿勢。可動域は制約、現在角度は変化する状態。 |
| 最初に決めた動きと、途中で確認する動きの違いは？ | 状況変化に気づき修正する必要性 | フィードバックには検出と修正の仕組みが必要。観測だけで回避できるとは限らない。 |
| 人のお手本から学ぶには何を記録する？ | 観測と操作を対応付ける発想 | カメラ画像・関節角度・指令の時刻をそろえる。動画だけで指令が直接分かるとは限らない。 |
| 同じ位置のお手本だけで、別の位置にも対応できる？ | 学習データの偏りへの気づき | 成功は保証できないが、絶対に不可能とも言えない。汎化と頑健性を区別する。 |
| 汎化を確かめるにはどこで試す？ | 学習に使っていない条件で評価する発想 | 到達可能な範囲で試す。補間・外挿は簡単な一次元の例で説明し、訓練範囲内なら必ず成功するとは言わない。 |

## 第1章へつなぐ（PDF pp.3–5）

まず LeRobot を、データ収集・管理、方策の学習、ロボットでの実行を支えるソフトウェア群として説明する。一つの学習済みモデルとの混同を避ける。対応機種やインストール方法の具体論は、必要になった時点で公式資料を確認する。

第1.1節への問いの例：「カメラ画像と操作指令の時刻がずれて記録されたら、お手本からの学習にどんな問題が起きそう？」

回答後に、同じ時点の観測と行動を対応付ける意味を整理する。続いて一連の試行（エピソード）へ進み、表形式データ・動画・メタデータの役割を少しずつ導入する。学習者がまだ答えていない問いの理解度を記録しない。

## コード実験の候補

時間の対応付けを理解した後、架空の画像ID・時刻・操作値を数行だけ用意し、操作列を一行ずらした場合に組がどう変わるかを一緒に見る。まず予想してもらい、その後に実装する。これはデータ対応の例であり、画像モデルの学習や実機実験ではない。

## 記録の見本

- 問い：汎化を確かめるにはどこで試す？
- 回答の要旨：まだ一度も置いていない位置で試す。
- 確認できた点：学習時と異なる条件で評価する発想がある。
- 補足した点：学習範囲内の未経験位置と範囲外を区別する。
- 未確認：補間・外挿を別の例で説明できるか。

この見本は教材用であり、別の学習者の実際の回答として記録しない。
