# ロボット学習ノート

ロボットについて個人で学ぶためのリポジトリ。教材の出典、理解した内容、疑問、実験を残す。整理そのものに時間をかけず、学習を再開しやすいことを優先する。

## 教材一覧

状態は `未着手`・`学習中`・`保留`・`一区切り`。この表だけで管理する。「一区切り」は全編終了に限らず、今回の学習目的を達成した状態。

| 教材 | テーマ | 状態 |
| --- | --- | --- |

最初の教材を受け取ったら登録する。気になるリンクだけの大量登録はせず、実際に取り組む教材を中心に追加する。

## ディレクトリ構成

```text
README.md                      # 運用方針と教材一覧
AGENTS.md                      # contributor guide
templates/material.md          # 教材ノートのひな型
materials/<教材ID>/README.md    # 出典・学習目的・ノート・次の一歩
materials/<教材ID>/notes/       # 長くなった場合だけ章別ノートを追加
materials/<教材ID>/code/        # 必要な場合だけ実験コードを追加
materials/<教材ID>/assets/      # 自作図など、小さな共有用ファイル
local/<教材ID>/                # PDF原本・動画・データ・生成物（Git対象外）
```

教材IDは `robotics-basics` のような短い英小文字の kebab-case。名前が衝突する時だけ著者・大学名などを加える。PDF・Web・YouTube・大学講義で構成を変えない。講義シリーズは原則一教材とし、各回をノート内で扱う。空のディレクトリは先に作らない。

## 教材を追加する

1. `materials/<教材ID>/` を作り、`templates/material.md` を `README.md` としてコピーする。
2. タイトル、著者・提供元、URL、版や公開年（分かる範囲）、学習目的を記入する。分からない情報は推測せず未確認とする。
3. このページの教材一覧に、教材ノートへの相対リンクを追加する。
4. 原本を保存する場合は `local/<教材ID>/` に置き、教材ノートに保存先を書く。

例：`mkdir -p materials/robotics-basics` の後に `cp templates/material.md materials/robotics-basics/README.md`。

## 学習の進め方

1. 教材ノートの「次の一歩」から、その回に扱う範囲を決める。
2. 日付と参照位置（章・ページ・見出し・動画の時刻）を添え、自分の言葉で要点を残す。
3. 教材の説明、自分の解釈、実験で確認した結果を区別する。疑問は未解決のまま記録してよい。
4. 終了時に「次の一歩」を更新する。状態が変わった時だけ教材一覧も更新する。

最初は教材ごとに一つの Markdown ファイルで十分。読みにくくなったら `notes/01-topic.md` などに分割してリンクする。同じ内容を複数箇所に転記しない。教材をまたぐまとめは、必要になってから追加する。

## 原本・コードの扱い

外部教材は出典リンクを基本とし、PDF・動画・データの原本は `local/` に保存する。共有可能と確認した小さな資料だけを意図的に Git 管理へ追加する。ノートには必要な引用と参照位置を残し、教材全文の複製は避ける。

実験コードを追加したら、その教材フォルダに依存関係、実行コマンド、確認方法を記載する。乱数シードや実行環境が結果に影響する場合も記録する。共通のビルド・テスト環境や CI は現時点では設けず、必要性が出てから導入する。

## Git / GitHub の運用

個人学習の小さな更新は `main` に直接コミットしてよい。大きな実装や構成変更は必要に応じてブランチ・PRを使う。

- 教材追加、一回の学習、実験の完了など、意味のある区切りでコミットする。
- `git status --short` と `git diff` で対象を確認し、`git add <対象パス>` で必要なファイルだけステージする。
- `git diff --cached` と `git diff --cached --check` を確認する。コード変更時は記載した確認方法も実行する。
- メッセージは `Add robotics basics material` や `Record forward kinematics notes` のように、変更内容を簡潔に書く。
- 区切りのよいコミット後に `git push` する。認証情報、ローカル原本、大きな生成物を含めない。

運用上の新しい決まりはまずこの README に記載し、管理ファイルや自動化を必要以上に増やさない。
